# D-Map — Phase 1

「練習をもっとオープンに、つながりをもっと自由に。」

ダンサーが東京都内の練習会・セッションを地図と日時から探す、QAエンジニア応募向けのポートフォリオです。**すべて架空のデモデータ**です。登録・認証・投稿・API・データベースは実装していません。

## 起動

Node.js 22.12以上のLTS（開発時は24）とnpmを使用してください。

```sh
npm install
npm run dev
```

表示されたローカルURLをブラウザで開きます。PowerShellで `npm.ps1` の実行ポリシーエラーになる場合、各コマンドの `npm` を `npm.cmd` に置き換えてください。ポリシーの変更は不要です。

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm run preview
```

APIキーは不要です。ただし初回の依存関係インストール、OpenStreetMapの地図タイルと任意のGoogle Fonts表示にはインターネット接続が必要です。フォント取得に失敗してもシステムフォントで表示します。地図が取得できない場合も一覧・検索・詳細は利用できます。

```text
src/
  App.tsx                      検索条件・選択イベントの状態を管理
  main.tsx                     React起動、CSS読み込み
  styles.css                   レスポンシブ表示、地図ピンの見た目
  types/event.ts               イベントと検索条件の型、選択肢
  data/events.ts               架空の8件（公開7件・グループ限定1件）
  services/eventService.ts     公開イベントの取得口
  lib/search.ts                UIに依存しない検索関数
  lib/search.test.ts           公開境界・日時境界・絞り込みの単体テスト
  lib/format.ts                日本時間・参加費の表示
  components/
    SearchForm.tsx             入力・検証・検索実行・リセット
    EventMap.tsx               Leafletの生成・破棄、ピン、概要ポップアップ
    EventList.tsx              一覧と0件案内
    EventDetail.tsx            キーボード操作可能な標準dialogで詳細表示
```

`DanceEvent` はデータの形を統一する設計図です。`visibility` は `public | group` に限定し、タイプミスを検出します。

`getPublicEvents()` で画面へ渡す前に公開分へ限定し、`filterEvents()` でも再確認します。Phase 1のgroupデータは架空のテスト用で、配信JavaScriptからは参照できます。**本物の機密データをフロントに含めてはいけません。** Phase 2ではFlask側で認証・所属判定を行い、権限のあるデータだけを返してください。

`filterEvents()` は「配列と条件を受け取り、新しい配列を返す」純粋な関数です。Reactや地図がなくても検証でき、入力配列も変更しません。地図と一覧は同じ検索結果を受け取るので、表示対象がずれません。

LeafletはReactとは別に地図を管理するため、`useEffect` の終了処理で地図・レイヤー・ResizeObserverを解放します。イベント文言はReactの通常のテキスト描画、ポップアップはDOMの `textContent` を使います。HTMLとしての挿入はしません。ピンの番号だけは内部生成した整数を使います。

## 日時検索の仕様

- データは `2026-10-24T23:00:00+09:00` のようにISO 8601とUTCオフセットを明記。
- 検索入力・画面表示はすべて日本時間（Asia/Tokyo）。端末のタイムゾーンに依存しません。
- 日付未指定なら日時で絞り込みません。時間を指定するときは日付が必須。
- 日付のみ：その日0:00から翌日0:00。開始のみ：その時刻から翌日0:00。終了のみ：当日0:00から終了時刻。
- 両時刻を指定して終了が開始より早ければ、終了を翌日として扱います。同時刻は入力エラーです。
- 検索区間とイベント区間の重複は `eventStart < searchEnd && eventEnd > searchStart`。開始を含み終了を含まない区間として扱うため、境界で接するだけなら対象外。
- 例：10/25の00:30〜01:00で、10/24の23:00〜10/25の02:00のイベントが見つかります。
- ジャンル・種別・日時はAND条件。検索ボタンで適用し、リセットで全公開イベントに戻します。

## 手動確認（QA観点）

| 操作                               | 期待結果                                                     |
| ---------------------------------- | ------------------------------------------------------------ |
| 初期表示                           | 東京中心の地図、公開7件のピンと一覧、デモ表示、OSM著作権表示 |
| ピンをクリック                     | イベント概要、詳細ボタンを表示                               |
| 一覧またはポップアップの詳細を選択 | 全項目を表示。閉じるボタン・Escapeで戻れる                   |
| 10/25 00:30〜01:00                 | MIDNIGHT POP SESSIONだけが表示                               |
| 10/24 23:30〜01:00                 | 同じ深夜イベントが表示                                       |
| HOUSE・ワークショップ              | 0件案内。ピンも0件                                           |
| リセット                           | 入力と結果が全公開7件へ戻る                                  |
| 幅375px・キーボード操作            | フォーム→地図→一覧が縦に並び、横スクロールなく操作できる     |
| 地図タイル通信失敗                 | 案内が表示され、一覧と詳細を操作できる                       |
| 非公開データ確認                   | グループ限定イベントがピン・一覧・詳細に出ない               |

自動テストは区間重複、端点、深夜、日付単独、時間片側、AND条件、0件、入力エラー、公開境界、データの整合性を確認します。ブラウザの見た目やタイルの取得成功は手動確認も必要です。

## Phase 2への接続

Flask API導入時は `services/eventService.ts` を非同期の `fetch` 呼び出しへ置き換え、Appにロード中・取得失敗の状態を追加します。レスポンスは実行時にも検証してください。日時はオフセット付きISO 8601を保ち、検索仕様をAPI側と共有します。認証・グループ権限の判定はサーバーで行います。この段階ではダミー認証や未実装ボタンを置いていません。
