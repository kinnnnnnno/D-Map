# Phase 2.2〜3.2 テスト計画・受け入れ項目

## 方針と実行方法

- pytest：各ケース独立のSQLiteファイル。認可・CSRFを有効にし、HTTPとして検証。専用run_tests.pyで共有TEMPの権限問題を避ける。
- Vitest：既存検索/日時/県OR/ページ/マーカー/安全表示領域に、APIエラー・CSRFクライアント・人数表示を追加。
- 既存E2E：固定15件のAPI fixtureで従来80件を維持。旧同期デモハーネスも検証専用で保持。
- 新規E2E：一時SQLiteの実Flask5001とVite4173。通常の開発DB/鍵を変更しない。CSRFを無効にせず、複数ブラウザコンテキストを使う。外部タイルはスタブ、フォントは遮断。
- 実行：backendで`.\.venv\Scripts\python.exe run_tests.py -q --tb=short`、ルートで`npm.cmd test` / `npm.cmd run typecheck` / `npm.cmd run lint` / `npm.cmd run build`。Edgeは`$env:PLAYWRIGHT_CHANNEL='msedge'; npm.cmd run test:e2e -- --workers=1 --timeout=90000`。統計の5ユーザー作成ケースだけ上限180秒。
- E2EはWindows/Edge、1280×960・LAと375×812・JSTの2構成。モバイル相当は実機ではない。既存日時ケースは2026-10-19 00:30 JSTを基準に時計を進める。

## Phase 3全体の受け入れテスト（開発者が実機でも確認する項目）

以下は手動実施済みチェックリストではない。自動化で確認した範囲は上表および実行記録を参照。

1. 空の開発DBにupgrade→seed-demoを2回実行し、15件のままである。以前に作成/編集した予定が上書きされない。
2. 未ログインで公開検索、東京＋神奈川15件、日時/ジャンルAND、ページ切替、地図の中心/ズーム保持、スマートフォンの拡大/ピンチを確認。
3. API停止中は失敗と再試行、応答遅延中は読み込み、成功した空配列だけは0件になる。
4. 架空メールで登録→非公開プロフィール編集→ログアウト→再ログイン。任意年齢を入力しなくても登録できる。
5. 未認証POST、CSRFなし、別Origin、他人のイベント変更を拒否。ブラウザのボタン表示だけに依存しない。
6. 管理者Aがグループ・招待を作る。メンバーBが別ブラウザでリンク/コード参加する。部外者Cは参加前に所在地・日時・詳細・統計をURL直打ちでも取得できない。
7. Aは限定予定を作成/編集/中止/削除でき、Bは閲覧/参加できるが変更不可。公開予定は作成者本人だけ変更できる。
8. 期限切れ/無効化した招待で新規参加できない。コードを再取得するAPIがない。
9. 参加予定0/1→参加1/1・残り0→取消0/1。他人の取消指定を拒否。定員なし、飛び入り表示、中止後の新規参加拒否を確認。
10. 別ブラウザ2つが最後の枠を同時に操作し、一方だけ成功。参加済み人数より小さい定員への変更を拒否。
11. 同意済み5人・同年代の架空データで対象数/人数/割合/平均を表示。非同意者・生年だけから正確な平均を推測しない。
12. 0〜4人と少数年代セルはAPIにも内訳/平均/対象人数がない。5人から1人が同意取消すると再取得後に非表示。サブジャンルで二重計上しない。
13. 詳細・アカウント・編集画面のTab/Escape、フォーカス復帰、背景スクロール、狭い画面の内部スクロールを確認。
14. ログアウト直後に限定ピン/詳細が画面に残らず、古いCookieも使用できない。戻る/再読込/別端末のセッションも確認。
15. 本番チェックリストの未実装項目を確認し、自動テスト成功だけでインターネット公開しない。
