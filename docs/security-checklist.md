# セキュリティ確認と本番公開前の残課題

2026-10-28の公開準備では、公開可否未確認の詳細住所を架空fixtureへ置換した。元の実測はGit除外領域で改変せず保持する。ローカルGitオブジェクトや除外ファイルにも残存し得るため、[公開準備記録](publication-preparation.md)を確認し、作業フォルダーや `.git` を丸ごと配布しない。

本実装はローカル学習・ポートフォリオ用。本番公開の承認や第三者監査を意味しない。テストデータはexample.invalidと架空の名前だけを使用する。

## 実装済みの防御

- Werkzeug scrypt。平文パスワードを保存/応答しない。12〜128文字、ボディ上限32KiB。
- Flask-Login。HttpOnly、SameSite=Lax、最終アクセスから8時間の有効期間（Flask標準の継続更新）。本番モードはSecure。
- Flask-WTFのCSRFをログイン・登録も含むすべての更新へ適用。Originがある更新は同じhost_urlであることも確認。ViteはHostを保持し、保護を迂回しない。
- 本番D_MAP_ENV=productionでは環境変数SECRET_KEY必須。開発鍵はinstanceにランダム生成して永続化、Git除外。固定のテスト用鍵/架空ユーザーはテスト構成だけに限定。
- ログアウトで全既発行セッション世代を失効。ブラウザの限定キャッシュ/進行中取得も破棄。
- 公開作成者/限定管理者の更新権限。検索/地図/詳細/参加/統計に共通のサーバー可視条件。部外者404。
- 招待は暗号学的乱数、ハッシュ保存、24h期限、管理者による無効化。フラグメントURL、コードの再取得APIなし。
- FKと複合PK、SQLite書込みロックによる定員整合性。参加の対象ユーザーはセッション本人だけ。
- React/DOM textContentによるテキスト表示。危険なHTML描画なし。入力はサーバーでも検証。
- 本人用以外にメール/年齢情報を返さない。メンバー一覧はid/name/roleのみ。
- 年齢/ジャンル同意は初期false・取消可能。5人未満/少数セルはサーバーで全内訳抑制。非表示の対象人数・平均・元データをAPIに含めない。
- APIはno-store、nosniff、Referrer-Policy:same-origin。DB・鍵・.env・仮想環境をGit除外。

## 公開前に必須の未実装・未検証項目

- メール確認、パスワード再設定/変更、ログイン/登録/招待試行のレート制限、アカウントロックと不正利用検知。
- 登録時のメール存在推測への追加対策（現状409と成功の差がある）、アカウント削除・データ保存期間・同意履歴/規約・未成年向け運用設計。
- 管理者交代、脱退/強制退出、ユーザー停止とセッション運用、問い合わせ/モデレーション・監査ログ。
- HTTPS＋本番WSGI、リバースプロキシのHost/HTTPS伝達と信頼境界、TRUSTED_HOSTS、CSP/セキュリティヘッダー、監視/バックアップ/リストア実地訓練、鍵ローテーション、依存脆弱性監査。
- DB/鍵がクラウド同期フォルダーにある環境では保管先/ACL/バックアップ/共有設定を見直す。SQLiteのネットワーク共有・複数ホスト・大規模負荷は未検証。
- 統計は取得時点の表示。サーバーの次回GETは同意取消を即時反映するが、他者が開いた画面の自動更新や取得済み内容の回収は行わない。「統計を更新」で再取得する。
- 5人閾値/少数セル全抑制でも、既知情報や繰り返しの参加変更からの差分推測を完全に防ぐ保証はない。公開範囲、遅延・固定集団による集計等を公開前に再検討する。平均年齢は法律上の年齢判定ではない。
- 実機iOS/Android、Firefox、スクリーンリーダー、侵入/負荷/第三者ユーザーテストは未実施。

## BUG-024：住所再検索の制限

- 検索語の正規化は保存住所を書き換えない。元の住所と検索候補・座標の一致は自動保証しない。
- 最大3形式、1通信6秒、完了後1.1秒間隔、共有キャッシュ・ロックを適用。429/障害に対する自動リトライなし。
- 広域候補を番地精度として表示しない。位置確定はUIの誤操作防止であり、APIの認可・座標検証を代替しない。
- 公開Nominatimは少人数の開発限定。本番拒否を維持。複数ホスト運用はこのファイルロックで制限できないため、共有レート制御・契約/自前サービスを別途設計する。
- 住所・座標は外部送信される。非公開の個人宅等は送信しない。新規の有料契約・キー追加・DBマイグレーションは行っていない。

## Phase 3.2.4：都道府県自動判定・比較データ

- 住所/候補から判定できない場合のみ正式県名を補完する。未判定の保存を禁止し、住所変更で旧県・確定座標を破棄する。
- 明確な住所先頭の県と保存prefectureの矛盾をサーバーでも拒否する。住所省略時の補完を許可するが、境界ポリゴン/建物入口の一致を検証したものではない。
- 手動逆検索と住所・補完県の既知の矛盾は位置確定を止める。推定を確定的な住所として保証しない。
- 比較は公開施設10件に限定。公開Nominatimへの追加通信0、Geolonia公開データを間隔・キャッシュ・転送量/通信回数・タイムアウト制限付きで取得。アプリの依存・本番プロバイダーは変更していない。
- Geolonia派生データにはCC BY帰属・加工表示を付与。ABRの地番追加規約ページは403で全文取得できず、本番導入前の確認を残す。Googleの地図/保存制約に合わない組合せを有効化しない。
- APIキー・個人宅・利用者の住所を比較データへ含めない。検証用依存・生データキャッシュはbackend/instanceでGit管理外。公開施設の抽出結果のみdocs/fixturesへ記録する。

## Phase 3.2.5：Google検証ツール（アプリ未導入）

- [評価手順](google-geocoding-evaluation.md)を用意。キーは現在プロセスの `GOOGLE_GEOCODING_API_KEY` だけから取得し、`.env`を自動読込せず、Viteへ渡さない。Google Cloud/請求先/キーの作成やAPI有効化は実施していない。
- dry-runが既定。実通信・課金可能性・Cloud上限確認・規約確認の4フラグとキー、対話端末が必要。上限確認は本人の宣言であり、ツールによるCloudの実効制限の検証ではない。通知型の予算だけを支出停止策と扱わない。
- 既存公開施設のハッシュ一致を検証し、1回最大10件、1.1秒間隔/6秒タイムアウト/応答上限。任意住所・任意URL・リダイレクト・自動再試行を許可しない。HTTP/API拒否時は残りも停止。
- Google応答本文・error_message・URL・例外本文をログへ出さず、出力に反射されたキーも除去する。キー漏えい時は本人が無効化する。サーバーRESTキーはAPI+送信元IP制限、将来のブラウザキーは別キー+referrer制限にする。
- Google候補は処理中メモリと帰属付き対話表示のみ。ファイル・DB・キャッシュへ保存せず、リダイレクト時は通信禁止。端末の録画/ログ/PowerShell transcriptの無効化は本人確認が必要。公開施設のGoogle応答もGitに追加しない（上の一般比較結果とは扱いを分ける）。
- Google非EEA向け規約の地図なし利用/非Google地図との併用禁止、条件付き保存例外を確認した。CLIは地図を表示せず、既存Leaflet・イベントAPI・DBを変更しない。保存例外を無期限の全員共有イベント座標の許可とみなさない。
- 実際のGoogle精度、実キーの制限、請求/上限、契約の適用、端末のログ設定は未検証。専用モックテストとdry-runの成功を、実API成功や本番公開可能の証明にしない。
- 回帰E2Eで初回セッション取得の競合を確認：テスト用登録時のCSRFヘッダーとCookieが不一致で400となった。統計テストの前提Cookieを画面より先に確立する修正後、PC/モバイルは成功。認証コード・CSRF保護は変更していない。開発モードの同経路の通常UIでの再現性・本番影響は未確認で、別課題として調査が必要。
