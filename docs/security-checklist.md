# セキュリティ確認と本番公開前の残課題

本実装はローカル学習・ポートフォリオ用。本番公開の承認や第三者監査を意味しない。テストデータはexample.invalidと架空の名前だけを使用する。

## 実装済みの防御

- Werkzeug scrypt。平文パスワードを保存/応答しない。12〜128文字、ボディ上限32KiB。
- Flask-Login。HttpOnly、SameSite=Lax、最終アクセスから8時間の有効期間（Flask標準の継続更新）。本番モードはSecure。
- Flask-WTFのCSRFをログイン・登録も含むすべての更新へ適用。Originがある更新は同じhost_urlであることも確認。ViteはHostを保持し、保護を迂回しない。
- 本番D_MAP_ENV=productionでは環境変数SECRET_KEY必須。開発鍵はinstanceにランダム生成して永続化、Git除外。固定のテスト用鍵/架空ユーザーはテスト構成だけに限定。
- ログアウトで全既発行セッション世代を失効。ブラウザの限定キャッシュ/進行中取得も破棄。
- 公開作成者/限定管理者の更新権限。検索/地図/詳細/参加/統計に共通のサーバー可視条件。部外者404。
- 招待は暗号学的乱数、ハッシュ保存、24h期限、管理者による無効化。フラグメントURL、コードの再取得APIなし。
- FKと複合PK、SQLite書込みロックによる定員整合性。参加の対象ユーザーはセッション本人だけ。
- React/DOM textContentによるテキスト表示。危険なHTML描画なし。入力はサーバーでも検証。
- 本人用以外にメール/年齢情報を返さない。メンバー一覧はid/name/roleのみ。
- 年齢/ジャンル同意は初期false・取消可能。5人未満/少数セルはサーバーで全内訳抑制。非表示の対象人数・平均・元データをAPIに含めない。
- APIはno-store、nosniff、Referrer-Policy:same-origin。DB・鍵・.env・仮想環境をGit除外。

## 公開前に必須の未実装・未検証項目

- メール確認、パスワード再設定/変更、ログイン/登録/招待試行のレート制限、アカウントロックと不正利用検知。
- 登録時のメール存在推測への追加対策（現状409と成功の差がある）、アカウント削除・データ保存期間・同意履歴/規約・未成年向け運用設計。
- 管理者交代、脱退/強制退出、ユーザー停止とセッション運用、問い合わせ/モデレーション・監査ログ。
- HTTPS＋本番WSGI、リバースプロキシのHost/HTTPS伝達と信頼境界、TRUSTED_HOSTS、CSP/セキュリティヘッダー、監視/バックアップ/リストア実地訓練、鍵ローテーション、依存脆弱性監査。
- DB/鍵がクラウド同期フォルダーにある環境では保管先/ACL/バックアップ/共有設定を見直す。SQLiteのネットワーク共有・複数ホスト・大規模負荷は未検証。
- 統計は取得時点の表示。サーバーの次回GETは同意取消を即時反映するが、他者が開いた画面の自動更新や取得済み内容の回収は行わない。「統計を更新」で再取得する。
- 5人閾値/少数セル全抑制でも、既知情報や繰り返しの参加変更からの差分推測を完全に防ぐ保証はない。公開範囲、遅延・固定集団による集計等を公開前に再検討する。平均年齢は法律上の年齢判定ではない。
- 実機iOS/Android、Firefox、スクリーンリーダー、侵入/負荷/第三者ユーザーテストは未実施。
